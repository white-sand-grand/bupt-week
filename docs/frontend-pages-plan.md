### Part C — 微信内体验：自动识别，不是等点击

用户原话："微信内体验应该是自动识别企业微信账户登录，如果识别不了再跳转到企业微信手动登录。"

所以不是"在微信里显示一个企业微信登录按钮等人点"，而是：

```
进入页面
  → 检测在微信 webview 里（UA 含 MicroMessenger）
  → 且未登录
  → 且本次会话没试过（防循环）
  → 自动跳 /api/auth/wecom/start
      → app.bupt.edu.cn 尝试自动识别企业微信身份
      → 识别成功：直接回到我们 callback，登录完成
      → 识别失败：app.bupt 显示它自己的手动登录页（学号密码），
        用户填完照样回到我们 callback
```

**关键点**：手动登录那一步是 app.bupt 自己的页面，不用我们做。
我们只需要"自动发起"+"防循环"+"失败后有兜底"。

**防循环**：用 `sessionStorage` 记一个"本次会话已自动试过企业微信"的标记。
自动发起前检查，回调带 error 回来时清掉标记并显示我们自己的学号密码表单——
那是最后兜底，不能再自动重试，否则用户卡死在循环里。

### Part D — 登录不是门禁（重要设计决定）

用户原话："把登录设计在页面里，不设计成不登录无法进入，只是没有数据。"

两个参考库都印证了这个做法：

- **MYUCLOUD**：README 原话"顶部课表或 `#timetable` 可直接打开课表页，
  **无需先登录 UCloud**……查看和切换已保存的周次**不请求教务系统，也不要求登录成功**"。
  `AuthBar.vue` / `JwglAuthBar.vue` 是常驻顶栏组件。
- **where_to_study**：`QmplusLoginSettings.jsx` 是设置面板，不是入口拦截。

所以本项目的形态：

```
┌─────────────────────────────────────┐
│ BUPT-week        [登录 / 张三 退出]  │  ← 登录是常驻元素，不挡内容
├─────────────────────────────────────┤
│  [课表]  [作业]                      │  ← 视图始终可切
├─────────────────────────────────────┤
│  未登录：显示"登录后查看课表"空状态    │  ← 空状态，不是登录墙
│  已登录：（第 2/3 期填真实数据）       │
└─────────────────────────────────────┘
```

未登录时页面照常进、照常切视图，只是没有数据。
这一条同时给第 2 期留了好处：课表缓存不登录也能看（沿用 MYUCLOUD 的做法）。

### Part E — viewport 与触摸目标

- `index.html` 已有 viewport ✓
- 按钮/输入框触摸区域不小于 44px（微信里是手指点，不是鼠标）

**验收**：Playwright 移动端模拟（`devices['iPhone 13']`）+ 微信 UA：
企业微信流程自动发起、普通浏览器不发起、未登录能进视图看到空状态、
手机宽度下不错位。
